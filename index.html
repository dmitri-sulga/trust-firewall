Where the method breaks

Track metrics

Tracks are synthetic. The rule-breaking tracks are deliberately clear-cut, built past each threshold to show which rule fires, not how often it would fire on real traffic. Why location forgery is worth modelling: according to an indictment unsealed in the Eastern District of New York in August 2024, two defendants allegedly sold hacked smartphones and fraudulent apps to more than 800 rideshare drivers, one of them a GPS-spoofing app that made a driver appear to be in an area with surge pricing. The release says that, as alleged, between November 2018 and August 2024 the scheme caused passengers to pay millions of dollars in fraudulent surge fees. It also says the defendants installed outdated versions of the rideshare app on the devices so that security features in newer versions would not detect the scheme's apps, which is a device-integrity gap that track physics does not close. Source: US Attorney's Office, EDNY, press release

Position is ground truth: each ring's accounts sit together whether or not the detector linked them, and every account keeps its place when an attack slider moves (the ring-size slider re-scales the picture). Colour and outline are the detector's output.

Ring sizes scales the six rings (none goes below two accounts); legitimate accounts scale with them, so the fraud share stays put (it is shown under the counters). This is not an attack, but small rings are harder: a two-account ring is a single link, which is also what two people sharing a phone look like. On its own it scores at most 2.0, below the cut of 2.25, so it is flagged only if a stray link joins it to a larger cluster. A larger setting contains the smaller one's accounts and the links inside each ring, so the tiles move without a new random draw. The path is still not strictly monotone: an added account can itself be one the detector misses, and a stray link can pull a legitimate account into a cluster.

Proxy obfuscation gives more ring accounts their own fingerprint, removes links inside rings and adds random links across the population. It is not strictly monotone either: an added random link can merge two fragments back above the cut. The name is shorthand: a proxy or an anti-detect browser hides a shared device or IP address, not a shared card or delivery address, yet the slider thins ring links of every kind at the same rate, so it hands the attacker more than proxies alone would.

Temporal spread spreads a ring's sign-ups over more cohorts and removes links between cohorts. This assumes links are only drawn between accounts seen within the same time window; a shared card links two accounts whenever they sign up, and against that this attack does nothing. The scale starts at 10%: up to there every ring is still a single cohort. Between two steps the tiles can hold still while links disappear (watch the link count); they move when a cluster drops below the cut or splits.

Where this method stops working: the detector sees only the link graph. Two evasions are modelled. Proxy obfuscation gives accounts their own fingerprints, so the links inside a ring thin out; temporal spread registers a ring in separate cohorts, so it reads as unrelated groups. Push both sliders right and recall and AUC collapse. That collapse is arithmetic, not a discovery: the score is size times density, and the attack removes density. It is shown because a measurement that cannot fail is not a measurement; if removing the only signal left the AUC high, the evaluation would be leaking.The number worth arguing about is not the AUC, it is how few links a ring account can keep inside its ring before the graph stops seeing the ring; the line over the chart gives it for the settings above. Past that point no amount of graph work recovers the ring and a behavioural signal has to take over.The starting point is built the same way: a share of ring accounts is generated with their own fingerprint so that the detector has something to miss even with both sliders at their lowest. The false-positive rate is just as much a product of how this population is built: legitimate accounts here link only in pairs and chains, which sit on the floor of the score, so every false positive on screen is a legitimate account with a stray link into a ring. Real households, offices and fleet cards form triangles, which this score puts at 3.0 and flags, so on real data the false-positive rate would not be this low. These tiles describe this synthetic population, not a detector's skill on live traffic.

A calculator, not a result. Every input is yours to set, and none of the defaults is a measured or published figure. Precision is not an input: it follows from prevalence, recall and the false-positive rate, which is why a detector that looks precise on a balanced test set can be mostly wrong when fraud is rare. The two counts are expected values, so they need not be whole numbers, and the money is computed from them unrounded. The model is deliberately plain. It assumes a blocked fraud account's whole yearly loss is prevented and that the account does not return under a new identity, so the prevented figure is an upper bound; it charges each wrongful block once; and it leaves out the cost of running the detector and of reviewing its alerts. Recall and the false-positive rate are separate sliders here, while a real detector moves both at once when its threshold moves, so read a pair of them as one operating point.

What this shows, and what it does not

Everything on this page runs on synthetic data only: no company's data and no production logs. The same seed gives the same numbers on every load, and every detection threshold is a named constant with a comment next to it in the page source.

It shows mechanics: how each detector decides, and the point where its method stops holding. It does not show performance on real traffic. That can only be measured on production logs, with the metric and the false-positive budget fixed before the first run.
